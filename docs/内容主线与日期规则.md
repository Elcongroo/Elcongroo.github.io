# 技术框架与原稿收录

博客以 congroo 的技术思考与源码解读为主体。`/journey/` 是《高性能安全通信系统栈》的技术导航。

## 框架与关系

保留原图 01–13 的技术模块，以及 PQC、特殊网络场景、编程自动化、调试工具四条横向线索。文章的 `modules` 字段关联模块；模块篇数与索引自动生成。

分步路径分别解释 IKE 初始建链、ESP 出站、OpenVPN 用户态发送、PQC 接口依赖。每条路径注明适用范围；模块顺序不能误画成所有业务包的执行顺序。RDMA 是独立支线。新增步骤时核对先后关系、数据产物和相应源码文章。

点击模块后，高亮与右侧文章面板同步更新。动画只表达选中和交接，支持暂停、键盘和减少动态效果设置。关闭 JavaScript 时，正文、原稿图示和全部模块文章仍以静态内容保留。

## 收录与公开版处理

当前收录 63 份技术原稿。导入工具只读取外部私有发布清单中显式列出的文档，不自动发布源库新增文件。内部任务、采购安排、非技术个人规划和重复首页不进入公开文章库。

- 保留技术推导、代码、版本边界与图示；涉及特定机构的称谓和本机路径做泛化，文章注明处理范围。
- 删除重复标题和原库阅读统计；附录原有 H1 章节向下调整一级，代码块内的标题示例不变。
- MkDocs 提示转为引用块；已公开文档间的链接映射为博客地址。
- 244 张原稿 Mermaid 图在构建时渲染。扩展图语法只支持已检查的子集，不能静默丢弃不支持的图。
- 网络编程示例和只读快照脚本以独立 ZIP 提供，保留目录结构与文件校验值，不附带采集到的网络状态。
- `publication-sources.json` 保存源文件版本及源稿/公开正文的 SHA-256。导入核对命令见 README。

## 补充研究稿

六篇“系统栈：接口与边界”使用 `editorial: research`，在归档、模块索引和文章顶部显示待审阅状态。它们由 AI 协助整理公开依据，设计和测试方案未执行，不能混为原稿观点、实测结果或已采用架构。

若之后完成作者审阅，更新明确的审阅记录与正文边界；不要通过把 `conclusion` 改成 `verified` 表示审阅通过。实测验证与编辑审阅是两件事。

## 日期与证据

- `date` 为实际进入本站的日期；原稿页面明确显示“收录本站”，新文章显示“发布于”。RSS 的 pubDate 与结构化数据 datePublished 都使用此日期，不倒填历史。
- `src/data/manuscript-history.json` 记录源文档最早可追溯的 Git 留档日期与对应 commit。导入工具通过 `git log --follow` 生成，`--check` 同时核对。页面显示“原稿最早留档”，不将 Git 日期说成首次写作日期；无记录时明确未核实。
- `updated` 对应真实修订。晚于收录日期时展示“最后修订”；同日修订仍在文章更新记录中注明，不为每次构建自动改日期。
- 实验日志可填写 `occurred`，明确运行日期与本站收录日期。不要用原稿留档时间代替实验发生时间。

收录不等于重跑实验。LAB-002 归档 2026-09-23 单机 IPsec 实验：congroo 已确认亲自操作；Codex 本次核对历史文件，未重新运行。本地核对的十二份日志/PCAP/衍生文件逐字节匹配原实验校验清单。作者选择先公开页面摘要，原始证据与其校验清单不进入公开仓库；页面不展示虚假下载入口。

PCAP 只有十二帧、首对 ESP，不能用四次 ping 或 XFRM 的累计包数补造缺失抓包。运行版本依据原实验文档，与 6.0.3 / v6.6 源码基线分开；没有原始版本命令输出与调用栈的部分保持边界。

LAB-001 仍保留 Codex 执行、作者手工复现待完成的原有说明。作者操作确认不等于整篇文章所有机制均已实测，也不等于独立环境交叉验证。

## 编辑选择与研究状态

`featured-studies.ts` 管理三篇重点文章的固定版本源码坐标与观察边界，`StudyEvidence.astro` 附在原稿之外；禁止为了加入实验记录覆盖已审阅正文。

`research-status.ts` 区分当前重点、已有技术笔记、待验证研究和后续研究方向。这是栏目关注状态，不是熟练度、正式工作职责或已完成产品的声明。文章级结论仍以各自 `conclusion` 与证据为准。
